  Your backend was trying to use app.listen() on Vercel
  Vercel is SERVERLESS (not a traditional server)
  app.listen() doesn't work in serverless environment
  It times out after 30 seconds → FUNCTION_INVOCATION_FAILED

================================================================================
                            THE FIX (DONE ✅)
================================================================================

Your backend/src/server.js was changed FROM:

  if (process.env.NODE_ENV !== 'production') {
    const start = async () => {
      await testConnection();    ← This blocks serverless
      app.listen(PORT, ...);     ← This never completes
    };
    start();
  }

TO:

  if (process.env.NODE_ENV !== 'production') {
    app.listen(PORT, () => {     ← Only on local dev
      console.log(`Running on port ${PORT}`);
    });
  }

KEY CHANGES:
  1. Removed async wrapper
  2. Removed testConnection() 
  3. Removed try-catch with process.exit()
  4. Kept the NODE_ENV check (only runs locally)
  5. Kept module.exports = app (for Vercel)

================================================================================
                          WHY THIS HAPPENED
================================================================================

Traditional Server Model (Your Local Computer):
  1. npm run dev
  2. Server starts with app.listen(5000)
  3. Server runs forever
  4. Listens for requests continuously
  5. Request comes in → responds
  6. ✅ Works perfectly

Serverless Model (Vercel):
  1. Request comes in
  2. Vercel invokes your function
  3. Your code runs
  4. Tries to do: app.listen(5000)
  5. Waits for server to start... but then what?
  6. Never completes or returns response
  7. After 30 seconds: TIMEOUT
  8. ❌ Error: FUNCTION_INVOCATION_FAILED

The misconception: Treating serverless like a traditional server!

================================================================================
                        MENTAL MODEL SHIFT
================================================================================

BEFORE (Wrong for Serverless):
  Startup Code
       ↓
  app.listen(5000) ← Blocks forever
       ↓
  NEVER returns
       ↓
  TIMEOUT → Error

AFTER (Correct for Serverless):
  Request comes in
       ↓
  Express handles it
       ↓
  Returns response
       ↓
  Function completes
       ↓
  Ready for next request

KEY INSIGHT:
  You don't need to START the server on Vercel
  The server is already running (provided by Vercel)
  You just export the Express app
  Vercel handles everything else!

================================================================================
                      HOW TO RECOGNIZE THIS PATTERN
================================================================================

RED FLAGS (Will cause this error):
  ❌ app.listen() outside if (NODE_ENV !== 'production')
  ❌ await testConnection() in production code
  ❌ process.exit() being called
  ❌ while(true) loops
  ❌ setInterval() without cleanup
  ❌ Server starts on every request

GOOD PATTERNS (Works on Serverless):
  ✅ app.listen() only in development
  ✅ module.exports = app for Vercel
  ✅ Functions that complete and return
  ✅ No port binding in production
  ✅ Stateless code (no global state)

================================================================================
                         KEY LEARNING
================================================================================

Serverless Concept:
  - Functions are stateless
  - Don't bind to ports
  - Start per request, not once
  - Complete quickly
  - Scalable automatically

Express on Vercel:
  - Export app as module
  - Vercel creates HTTP handler
  - No app.listen() needed
  - Works with NODE_ENV check for local dev

Mental Model:
  Traditional: "Start server, listen forever"
  Serverless: "Handle request, return response, done"
